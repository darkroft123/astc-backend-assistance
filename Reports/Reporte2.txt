📄 🧾 REPORTE COMPLETO DE ERRORES (LOGIN + JWT + SEGURIDAD)
1. Contexto

Durante la implementación del sistema de autenticación con:

Quarkus
SmallRye GraphQL
JWT (SmallRye JWT)
BCrypt

se presentaron múltiples errores en:

Login
Generación de token
Autorización con roles
2. Error inicial (GraphQL)
Error:
Unexpected end of JSON input
🔍 Causa raíz:

El backend no estaba respondiendo JSON válido, debido a excepciones internas no controladas.

👉 GraphQL UI intentaba parsear una respuesta vacía.

3. Error de autenticación
Error:
Failed to verify password
Unknown crypt string algorithm
🔍 Causa raíz:

El sistema esperaba password en formato BCrypt, pero en la base de datos estaba:

1234  ❌ (texto plano)

👉 BCrypt requiere algo como:

$2a$10$...
4. Error de diseño de seguridad
Problema:

Se mezclaron dos enfoques:

Tipo	Estado
Password plano	❌
BCrypt	✔ pero mal usado

👉 Esto generó fallos en:

PasswordHasherPort
BcryptPasswordHasher
LoginUseCase
5. Error JWT (CRÍTICO)
Error:
Signing key can not be created from the loaded content
🔍 Causa raíz:

Las llaves .pem:

❌ Formato incorrecto
❌ Generadas con herramientas incompatibles
❌ Tipo incorrecto (RSA vs PKCS8)
6. Error de autorización
Error:
DataFetchingException en listUsers
🔍 Causa raíz:

Header mal enviado:

"Authorization": "eyJhbGciOi..." ❌

En lugar de:

"Authorization": "Bearer eyJhbGciOi..." ✔
7. Solución aplicada (PASO A PASO)
✔ 1. Password seguro
Se generó hash BCrypt válido
Se actualizó la base de datos
✔ 2. Verificación correcta

Se usó:

passwordHasher.verify(plain, hash)
✔ 3. Generación correcta de JWT

Se implementó:

Jwt.issuer(...)
   .subject(...)
   .groups(...)
   .sign();
✔ 4. Llaves RSA válidas

Se generaron correctamente:

privateKey.pem (PKCS8)
publicKey.pem

Ubicación:

src/main/resources/
✔ 5. Configuración correcta
mp.jwt.verify.publickey.location=publicKey.pem
mp.jwt.verify.issuer=attendance-system

smallrye.jwt.sign.key.location=privateKey.pem
✔ 6. Header correcto
{
  "Authorization": "Bearer TOKEN"
}
8. Resultado final

✔ Login funcional
✔ JWT válido generado
✔ Roles funcionando (ADMIN)
✔ Endpoints protegidos (@RolesAllowed)
✔ GraphQL estable
✔ Seguridad completa operativa

9. Conclusión técnica

Los errores NO fueron de lógica de negocio, sino de:

❌ Configuración de seguridad
❌ Incompatibilidad de formatos (BCrypt, JWT)
❌ Uso incorrecto de estándares (Bearer token)
❌ Falta de consistencia en generación de llaves

👉 Este tipo de errores es común en integración de seguridad, no en lógica.
